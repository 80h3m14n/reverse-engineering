 Learn the underlying principles and techniques, then treat tools as replaceable implementations.

 However, I recommend these useful tool as TOOLS STILL MATTER, my reasons include:

1. The tool makes a technique easier — e.g., a good debugger helps you apply debugging techniques faster.
2. The tool saves time — automation can eliminate repetitive work.
3. The tool improves quality — a better editor, testing framework, or design tool can reduce errors.
4. The tool fits most people's  constraints — budget, device, experience level, team, ecosystem, etc.
5. The tool provides capabilities they otherwise don't have — for example, specialized analysis or visualization.

> The right tool can make learning a technique much more accessible.
